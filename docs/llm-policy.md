# t2linux LLM Policy

t2linux project allows LLM-assisted contribution for codes. However, unreviewed, untested, or low quality code generated by LLM (sometimes called vibe coding) is not allowed and can lead to a ban.
Also, you're required to disclose your LLM usage in the PR description and use Co-Authored-By: [model] if you used LLM for significant amount of code.
Moreover, we do not allow usage of LLM for writing issues, and title and description of Pull Requests (e.g. posting LLM output of bug reports, letting your "Agent" write an issue or PR on your behalf). You will be warned for first offense, but continuation of this behavior could lead to a ban.

## Special rule for submitting patches that could be submitted to the upstream Linux kernel

Please follow our LLM policy for PR (and disclose your usage), but follow [upstream Linux kernel guideline](https://docs.kernel.org/process/coding-assistants.html) for the patch file themselves. (tl;dr: no Co-Authored-By or Assisted-by in patches themselves, disclosure in the description is fine.)
